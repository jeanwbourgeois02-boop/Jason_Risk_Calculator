Built 2026-09-17 for engine/rates_vol (swaptions, caps/floors, SABR, Bermudan pricing --
options merge Phase 6, see [[diagnostics_module_naming]] for the sibling market-data
modules' naming pattern). Mirrors [[vol_marketdata_fx_vol_feed]] and
[[rates_marketdata_ois]] exactly: `RateVolBloombergSource` / `RateVolFileSource`,
`rate_vol_quotes` staging table (`ensure_rate_vol_quotes_table` / `write_rate_vol_quotes`),
`--probe` CLI mode, `.diag.json`.

**Schema quirk carried over from the consumer, not introduced here**: the task's
literal spec for `rate_vol_quotes`'s primary key
`(as_of_date, ccy, index, instrument, expiry_tenor, underlying_tenor, strike_offset_bp,
source)` does NOT include `vol_type`. This exactly mirrors
`engine/rates_vol/inputs.py`'s own `rate_vols` table, whose PK has the same shape
(`strike_or_ATM` in place of `strike_offset_bp`, also no `vol_type`). Practical effect:
writing both a LOGNORMAL and a NORMAL quote for the same node/source collides on the
PK and `INSERT OR REPLACE` means last-written-wins -- the earlier vol_type's row is
silently gone. Tests that need a specific vol_type's grid intact must filter to that
vol_type (and optionally one instrument, since instrument IS part of the PK and never
collides across SWAPTION vs CAP) before writing -- see `_only_vol_type` helper in
`tests/test_bloomberg.py`'s rates_vol_marketdata section.

**Ticker encoding (all UNVERIFIED, see module docstring's numbered probe list)**:
ccy -> 2-letter prefix by analogy with `rates_marketdata.OIS_CURVES` ticker roots (US,
EU, BP, JY, SF, CD, AD -- note EUR uses 'EU' here even though its OIS root is 'EE', to
match the task's own worked example). Expiry code: letter for sub-year (1M='A', 3M='C',
6M='F', borrowed from the OIS depo-tenor lettering already used elsewhere in this repo),
else zero-padded 2-digit year number. Underlying tenor: always 2-digit year number
(tenors in scope are all >= 1Y). Swaption ATM lognormal = `<prefix>SV<expiry><tenor>
Curncy` (e.g. `USSV0110 Curncy` = 1Yx10Y, the task's own worked example); normal =
`SN`; cap lognormal = `<prefix>CV<expiry> Curncy` (no tenor code -- caps have no
underlying-tenor axis); cap normal = `CN`.

**`atm_swaption_vol` interpolation gotcha**: tenor axis is interpolated first (plain
linear), expiry axis second (variance-time, `var = vol^2 * days`). This means a result
needing interpolation on BOTH axes is NOT guaranteed to sit within the min/max of the 4
raw grid corners (the two variance-time inputs are themselves tenor-interpolated, not
raw corners) -- only single-axis interpolation (the other axis landing exactly on a
staged node) is tightly bounded by the two relevant corner values. Caught this via a
failing test with a wrongly-chosen date once and again after fixing the date -- watch
for it if this function's test ever needs a new date: `(expiry_date - ref_date).days`
must actually fall between the *day-counts* of the intended bracketing tenor letters
(e.g. '6M' is ~182 days, not comparable by eyeballing calendar months against '1Y'/'2Y'
without doing the day-count arithmetic first).

Fixture `data/bloomberg/fixtures/rate_vol_snapshot_v1.json` (168 quotes, USD + EUR,
both vol types, SWAPTION 7 expiries x 5 tenors + CAP 7 expiries, `source:
"test-fixture-synthetic"`) was generated by a one-off script that imports the module
itself (`rvm.rate_vol_ticker` / `rvm.save_rate_vol_snapshot`) rather than hand-typing
168 rows, so tickers are guaranteed internally consistent with the module's own
encoding -- regenerate the same way if the encoding ever changes.
