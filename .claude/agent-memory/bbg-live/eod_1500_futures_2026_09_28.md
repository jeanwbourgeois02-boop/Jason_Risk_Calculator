**Rule as it stood that morning (superseded later on 2026-09-28 by [[one-close-1700-2026-09-28]]: one 17:00 daily close for every instrument, FX included):** a future's or a listed option's past close is Bloomberg's daily
`PX_LAST`, stamped 17:00 New York (`backfill.settle_stamp`); a live FUTURE_PX row keeps its old
stamp (`build_future_rows` stamps `snapped_at(as_of)`, 15:00 of the book date, which
`backfill.is_close_row` tells from the 17:00 close). FX closes are the 15:00 bar (BID/ASK mid).

**Built and reversed the same day, 2026-09-28:** the user first said the book's EOD is 15:00
New York for everything, so futures and options on futures were moved to the 15:00 TRADE bar:
`pull_marks.INTRADAY_TRADE_SIDES = ("TRADE",)`, a `sides` kwarg on
`fetch_intraday_close_series` (TRADE = one request per ticker, the bar's close, no mid), a
`snapped` kwarg on `build_future_rows` so `live.pull_once` could stamp its FUTURE_PX rows at the
press time, and bbg-backfill's matching side. The user reversed it within the hour; the source
files were restored to HEAD by the housekeeper and this lane's test hunks removed. None of those
names exist in the code now: grep before assuming any of them.

**Why:** two conventions on one P&L line (FX at 15:00, futures at 17:00) looked wrong for a
moment; the user chose to keep Bloomberg's own daily close for every listed instrument
(consistent with the 2026-09-22 decision "use px last like all other futures").

**How to apply:** do not propose a 15:00 bar for futures again unless the user raises it. If it
comes back, the reversed design above is the shape to rebuild.

**Traps met on the way:**
- Existing tests assert the substring "no hourly bar ending 15:00 New York" in
  `fetch_intraday_close_series` reasons: keep that phrase, append qualifiers in parentheses.
- A Python replace script fed through a bash heredoc did not match a source line ending in a
  backslash continuation (`...listed}) \`); the Edit tool did. Use Edit for such lines.
- Parallel lanes leave the shared test files (test_live.py, test_bloomberg.py) with their own
  uncommitted hunks (2026-09-28: two new `trades` columns in every positional INSERT). Never
  revert or reformat them; undo only your own hunks and report the rest.
- `test_close_completeness` (inventory, bbg-library's test in test_bloomberg.py) pins the stamp
  rule for a past FUTURE_PX row; any stamp-rule change flips it, and it is not this lane's.
