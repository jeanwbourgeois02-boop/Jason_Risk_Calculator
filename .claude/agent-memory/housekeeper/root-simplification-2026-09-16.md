On 2026-09-16 the user asked (twice, with sharpening wording each time) for the top-level
file list — the files shown alongside the owned folders data/, engine/, ui/, tests/, docs/
— cut to exactly three: one setup file, one launcher (backing the `pnl` command), one
Bloomberg diagnostics entry point. Final state, confirmed with the user's exact words
("I want 3 clear files below gitignore"):

- `1_setup.cmd` (originally `SETUP.cmd`) — the setup file. Pre-Python/pre-git bootstrap
  (installs Python + Git via winget, clones/updates the repo, then calls
  `py 2_launcher.py setup`). Cannot be folded into `2_launcher.py`: a `.py` file can't
  bootstrap the interpreter that would run it. Left as-is apart from the rename.
- `2_launcher.py` (originally `risk.py`) — the launcher (`start` subcommand, what `pnl`
  calls) plus `setup`/`doctor`/`freeze` subcommands. `requirements.txt` was removed from
  git; its contents live as `PACKAGES`/`DEV_PACKAGES` module-level lists in
  `2_launcher.py`, `IMPORT_CHECKS` is the matching verify list, `py 2_launcher.py freeze`
  regenerates `requirements.txt` on disk (git-ignored) for external tools. See
  [[setup-dependency-completeness]].
- `3_diagnostic.py` (originally `bloomberg_diagnostics.py`) — thin wrapper only: imports
  and calls `tools.bbg_diagnostics.main`. The real diagnostics implementation stays in
  `tools/bbg_diagnostics.py` (also used by `ui/tabs/header.py`'s "Check Bloomberg
  connection" button via the `data/bloomberg/bbg_diagnostics.py` shim) — this file adds no
  logic of its own, just visibility at root. Covered by
  `tests/test_risk_cli.py::test_root_bloomberg_diagnostics_is_a_thin_wrapper`, which patches
  `tools.bbg_diagnostics.main` and asserts the root file's `main` name is the same object
  (catches any future drift into a second implementation).
- `tools/bloomberg_terminal_probe.py` was deliberately NOT surfaced at root a second time:
  it's a different tool (zero-repo-import, meant to be copied alone onto the Bloomberg
  terminal machine), already reachable via `py 2_launcher.py doctor --bloomberg`. Surfacing
  two "Bloomberg diagnostics" files at root would recreate the exact duplication the user
  is objecting to; if this turns out to be the wrong pick, swap the wrapper's import, don't
  add a second root file.

**2026-09-16, later pass — numeric sort prefixes**: the user asked for the three root
files renamed so they sort 1/2/3 in a file explorer: `SETUP.cmd` -> `1_setup.cmd`,
`risk.py` -> `2_launcher.py`, `bloomberg_diagnostics.py` -> `3_diagnostic.py`. Because
`2_launcher.py` starts with a digit it is not a valid Python identifier, so it can never be
`import`ed by name again — `tests/test_risk_cli.py` now loads it via
`importlib.util.spec_from_file_location` and binds it to the local name `risk` so the rest
of the test file is unchanged. Every other reference across the repo (docs/README.md,
docs/HOW_IT_WORKS.md, docs/bloomberg-live.md, docs/launch-and-upload.md, tools/setup.ps1,
ui/launch.py, ui/tabs/market_data.py, data/bloomberg/backfill.py, and the `pnl` PowerShell
function text generated by `pnl_function_block()` in `2_launcher.py` itself) was a plain
text substitution of the old filename for the new one — grep the repo for the old names
before trusting any of them are still accurate.

**Why:** user's own words, twice — "after the folders on the left to only have three
things ... thats it", then "I want 3 clear files below gitignore ... the one which runs
bloomberg diagnostics" naming the third item explicitly this time. Standing instruction
never to add a second launcher or a second diagnostics file applies equally here. The
later numeric-prefix rename was a separate explicit request for file-explorer ordering.

**How to apply:** this item is now closed — do not re-open or re-investigate "where's the
third root file" or "what are the root files named" again; they exist as `1_setup.cmd`,
`2_launcher.py`, `3_diagnostic.py`. Any future new top-level file proposal should be
redirected into `docs/`, `tools/`, or folded into `2_launcher.py`'s subcommands, unless it
is, like `1_setup.cmd`, structurally unable to live inside `2_launcher.py`. If the
Bloomberg diagnostics implementation is ever restructured again, keep the root file a thin
wrapper (one import + `main()` call) so there is still only one real implementation. If
`2_launcher.py` is ever renamed again, remember the `import` restriction above and check
`tests/test_risk_cli.py`'s loader.
