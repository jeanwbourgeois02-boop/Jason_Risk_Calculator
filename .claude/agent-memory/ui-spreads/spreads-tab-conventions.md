Spreads tab renders `engine.spreads.book_spreads(conn, as_of, value_fn=priced_value_book)` inside `pricing_snapshot` (the reader's tuple is accepted directly), then one `engine.risk.research_spreads.research_spread_stats(keys, as_of)` call per render (not memoised: ~0.1 s, and the research DB changes on the research app's own runs, which no revision of ours sees).

- Shell interface: `layout` = `build_layout`, `register_callbacks(app, get_db_path)`, `BODY_ID`. tests/test_app.py requires the key `f"{BODY_ID}.children"` in `app.callback_map`, so the body callback must stay SINGLE-output. The drill-down is a second callback: Input(TABLE_ID active_cell) + State(DETAIL_STORE_ID, AS_OF_STORE_ID) -> Output(DETAIL_ID children, SELECTED_STORE_ID data); PreventUpdate on a cell with no known `row_id`. `SELECTED_STORE_ID` is static in the layout; the body callback reads it as State and pre-opens the drill-down after a re-render. `DETAIL_STORE_ID` (in the body) holds every open position's JSON payload so a click never rebuilds the book.
- Phase B (2026-09-25) main table = `positions` (status open), one row each, rows carry `id` = position_id. Grouped by family (calendar, benchmark, processing, substitution, other, bundle, pinned), |LTD| within; group boundary = top border by row_index. Two-row headers (merge_duplicate_headers): Spread / Level / Research (run date) / USD / P&L USD / Leftover. Levels are TEXT cells in the unit's decimals (`level_decimals`: bu/lb/gal 4, mmbtu/cwt 3, JPY/KRW 0, CNY 1 (g 2), else 2), since units differ per row. Research cells numeric, no sign colours (a level rise is not a gain for a short), shaded at |sigma| or |z| >= 2. Daily/MTD/LTD shown; 5d on Daily's hover, YTD on LTD's. "P&L note" text column: "excl. N" from `pnl_excluded`, or "filled".
- Width rule (housekeeper, 2026-09-25): every column in sight at 1680 px with no horizontal scroll. The section's inner width is ~1590 px; each cell renders ~2 px wider than its set width. So: fixed px per column (`COLUMN_WIDTHS_PX`, `BORDER_PX`, `WIDTH_BUDGET_PX`, tested), nowrap + ellipsis, `with_footer(widths=False)`. The Family column was dropped (the grouping and the name's hover say it). Order: name, legs, size | unit, entry, now, chg | $/1.0, Daily, MTD, LTD | research | leftover | note.
- Empty band above a Total line: under Dash 4.4, `ranking.with_footer`'s footer hides its th cells but each header row keeps 30 px. `pinned()` adds css `tr:has(> th) {display:none}` to the footer. It is a shared bug, so a fix in ranking.py is ui-shell's.
- Layout checks: the scratchpad has `run_ui.py <port>` (serves the golden book as of 2026-09-18) and a Chrome DevTools protocol screenshot script. My probe is `sp_probe.py` / `sp_probe.js` (port 8071 app, 9454 Chrome).
- Drill-down: research history 5y back to the as-of, entry as dashed trace, today's level as a marker, overlays only when our unit equals the research unit; entries table from `result["spreads"]` members; legs table = `level_legs` merged with the position's summed `legs` by instrument_id.
- Kept from Phase A as they were: closed spreads (spread rows + collapsed legs blocks), outrights (full figures), For review drawer, Data issues drawer (now also levels, research reasons; a research DB not found is ONE book-level line).
- Tests: fake result + fake research dict + fake `history_fn`; end-to-end with a tiny research DB via `COMMODITY_HISTORY_DB` env and a stub `ui.app` module; golden sample via `tests.golden_book.build_book`. On the sample the research app's first stats run is 2026-09-21, so as-of 2026-09-18 shows every research cell n/a.

**Why:** screens never recompute (CLAUDE.md "Tabs as views"); the fill must match the header; the redesign's "numbers first, definitions on hover" rule; research is context, never a mark.
**How to apply:** when spreads-engine's shape changes, touch `position_record`, `detail_payloads`, `spread_record`, `outright_record`, `review_record`. Phase C adds P&L history per spread (spreads-engine first).
