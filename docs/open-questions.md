# Open questions

Unresolved items from the data-contract review of `data/raw/HA_PNL_20260818.csv` and `data/raw/HA-portfolio vJean.xlsx` (2026-09-13). Each has a proposed default; the default is what the app assumes until the question is closed. Settled decisions live in `CLAUDE.md`.

## Assumptions in force, unconfirmed

- **NDF list.** BRL, TWD, KRW, IDR treated as non-deliverable (`instruments.is_ndf = 1`); TRY and MXN treated as deliverable. To be verified with the PB. Affects the cash ladder only (NDF legs carry `settles_cash = 0`). `data/ingest/bnp.py` hard-codes this list (`NDF_CCYS`) as provisional.
- **`as_of_date` from the BNP filename.** `HA_PNL_YYYYMMDD.csv` dated T → `as_of_date` = previous weekday (Mon–Fri); no holiday calendar yet. On a day after a US holiday the caller must pass `as_of_date` explicitly. To be replaced by the trading calendar when it exists.
- **PB FUTURES rows create no `trades`.** The BNP FUTURES row is one netted position with no fill dates; the ingest writes a `positions` row (and the instrument) only. Futures fills come from the xlsx `All FX trades` sheet (`C = contracts × 50 × fill`).
- **P&L identity tolerance in ingest.** The contract states `DTD Total = MV Base − Start Date Dirty MV`, `MTD Total = MV Base − Prev ME MV Base`, `DTD Total = DTD Trading` as identities; `bnp.py` checks them with its own float tolerance `PNL_TOL = 0.01 USD` (observed max deviation 6e-5 on the 08/18 file). Not a contract tolerance.

32. **BNP spot coverage is partial.** BNP `Fx` is quote-ccy→USD, so a pair spot is only derivable for USDXXX pairs (`1/Fx`). On XXXUSD rows `Fx = 1.0` and the spot is not derivable at all (`Price` is the forward outright); crosses need a row whose quote currency is the cross's base, which never occurs (there is no `USDEUR` row). On the 08/18 file `bnp_marks.py` emits SPOT for 14 of 18 pairs (none for AUDUSD, EURUSD, GBPUSD, XAUUSD) with a warning, and FWD_OUTRIGHT for all 19 `(pair, value_date)` keys. Does BNP expose a spot rate elsewhere (another column or file)? Default: partial `BNP_BVAL` SPOT coverage; reconciliation of XXXUSD pairs uses `FWD_OUTRIGHT` only.
33. **Bloomberg-machine Python prerequisites.** `pull_marks.py` needs Python ≥ 3.9 (`zoneinfo`, `dataclasses`) and `blpapi`. It builds `ZoneInfo("America/New_York")` at import; on Windows that needs the `tzdata` pip package or the script dies before writing any diagnostics. Nobody has confirmed the Python version, `blpapi` version or `tzdata` presence on the terminal machine. `docs/bloomberg-run.md` lists a preflight; the first probe run answers this.
34. **Probe broken date may be a non-business day.** The probe asks for the EURUSD outright at `--as-of + 30 days` without a calendar. If that date is a weekend or holiday, a failure on the direct request is ambiguous (bad field vs bad date). Default: if the probe fails on every candidate, re-run with an `--as-of` whose +30d is a weekday before concluding the field names are wrong. Better: let the probe pick the next weekday (bbg-data, when the first probe results are in).
35. **Batched tenor request classification.** `pull_marks.py` classifies the eight-ticker tenor request as a whole (`FIELD_EXCEPTION` if any one tenor ticker fails) while the CSV row can still be interpolated from the remaining tenors. Exit codes follow requested-vs-written keys, so this only affects the counts in the diagnostics report. Keep batch-level (default) or move to per-ticker classification once real responses show how often single tenors fail.
